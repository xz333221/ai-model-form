## ai-model-form: 新增 Agnes AI 供应商预设（用户反馈"连不上 agnes"）

### 问题排查
- 用户在 ai-model-form 项目里测试 agnes 模型连接失败。
- 探测结论：agnes API 端点(`apihub.agnes-ai.com`)网络完全正常 —— DNS 解析到 Cloudflare(104.18.x.x)，经本机系统代理(127.0.0.1:10808)转发，无 key 返回 401 属 OpenAI 兼容标准行为。**网络不是原因**。
- "连不上"根因判断：用户此前在表单手填了错误 endpoint（很可能填成 `platform.agnes-ai.com` 控制台域名，或漏 `/v1`）。
- Agnes AI 性质：OpenAI 兼容聚合模型 API（自家 agnes 系列 + glm-5.2/kimi-k3/deepseek-v4 等），Base URL = `https://apihub.agnes-ai.com/v1`，认证 `Bearer <key>`。

### 改动（4 处源码 + rebuild）
- `server/middleware.js`：`PROVIDERS` 数组新增 agnes；`BUILTIN_MODELS` 新增 agnes 模型列表(agnes-2.5-pro-alpha / agnes-2.0-flash / agnes-image-2.0 / agnes-video-v2.0)。
- `client/src/components/AddModelForm.vue`：`providers` 数组新增 agnes；`logoUrl()` 对 `icon==='agnes'` 返回内联 SVG data URI（紫蓝渐变圆角+A）—— 因 `@lobehub/icons-static-png` 无 agnes 图标(实测 404)，走 CDN 会破图。
- `client/src/i18n/zh-CN.js` + `en-US.js`：`provider.agnes = 'Agnes AI'`，计数注释 16→17。
- `npm run build` 成功(vite 1.53s)，agnes 已进 `dist/ai-model-form.mjs` 与 `.umd.cjs`。

### 潜在隐患（未处理，待观察）
- Node.js 原生 fetch(undici) 默认**不读** `HTTP_PROXY/HTTPS_PROXY` 环境变量。用户本机设了系统代理 127.0.0.1:10808（翻墙），但 server/middleware.js 的 `fetchLiveModels` 与 `/ai-model/test` 走 Node fetch 直连。若 agnes 端点国内需翻墙才稳定，server 端测试可能超时。必要时需给 server 加 undici `ProxyAgent` 支持。
